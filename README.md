# Shadrin Method website

Официальный сайт Shadrin Method. Stage 1 — предварительная многостраничная
версия на основе исходного лендинга. Сайт состоит из обычных HTML/CSS и локальных
изображений: сборка, JavaScript, платные сервисы и внешние ресурсы не требуются.

## Стандарт мобильной шапки (27.10.2026)

При ширине до 700 px шапка использует компактную двухуровневую раскладку: бренд и переключатель RU/EN на первой строке, все пять навигационных ссылок на следующих строках по необходимости. Общая раскладка задаётся исключительно через `assets/site.css` для EN/RU и будущих страниц. Не переносить переключатель языка под меню и не скрывать ссылки в неинтерактивные элементы. `scripts/check_browser.py` содержит регрессионные проверки высоты и расположения элементов.

## Стандарт заголовков сайта — SHADRIN TYPOGRAPHY V1 (27.10.2026)

**Обязателен для всех существующих и новых страниц**: EN, RU, страниц книг и будущих статей.
Единственным источником типографики заголовка первого уровня (H1) является `assets/site.css`.

- **H1:** `clamp(2.15rem, 4.8vw, 3.5rem)`, межстрочный интервал `1.17`, `letter-spacing: -.045em`, максимальная ширина `920px`; на экранах до 700 px — `clamp(2rem, 7.5vw, 2.6rem)`. Использовать один H1 на страницу, независимо от языка и длины заголовка.
- **Надзаголовок:** `.eyebrow`, 12px, золотистый цвет и общая разрядка. Не создавать локальных вариантов.
- **Стандартная зона заголовка:** `.page-hero` с отступами 52px сверху / 26px снизу; на мобильных — 40px / 22px. Для домашнего блока `.hero` сохраняется дополнительный нижний отступ под описание и кнопку, но размер H1 остаётся тем же.
- **H2:** общий базовый стиль `h2`; подзаголовки внутри длинной авторской истории `.author-story h2` допускают отдельный размер **только** для второго уровня и используют те же правила в RU и EN.
- **Переносы:** браузерные переносы без фиксированного количества строк. Осмысленное разделение двухчастного слогана на главной может сохраняться; остальные заголовки не разрезать принудительными `<br>` ради конкретной ширины экрана.
- **Новые страницы:** подключать общий CSS, использовать `.page-hero` и один `<h1>`; не задавать `h1`, `.page-hero` или `.hero` в индивидуальном `<style>` страницы. Корректировать дизайн заголовков сразу во всём сайте, а не через исключения.

Этот стандарт фиксирует **визуальную систему**, но не требует одинаковых формулировок заголовков: заголовок каждой страницы остаётся привязанным к её содержанию и потребностям посетителя.

## Раздел Articles / Статьи

Раздел называется **Articles** в англоязычном интерфейсе и **Статьи** — в русскоязычном. URL `/resources/` и `/ru/resources/` сохраняются для существующей перелинковки, hreflang и canonical. При добавлении статей использовать эти маршруты до отдельного решения о URL-архитектуре. Не возвращать Resources / Материалы как название вкладки навигации.

## Языковые версии

Английские страницы находятся в корне; русские — по пути `/ru/`. На каждой из пяти пар страниц есть переключатель RU/EN и взаимные `hreflang`-ссылки. Ссылки внутри русской версии ведут на русские разделы.

Русский текст главной страницы — перевод текущего англоязычного лендинга. Русский текст «О методе» следует авторскому файлу «О методе.docx» от 26.10.2026; это вступление, а не окончательный полный текст раздела. Русская биография переведена по действующей английской версии: использованы 2017 и 2022 годы, поскольку более ранний русскоязычный файл содержит устаревшую хронологию. Новые русские страницы временно закрыты от индексирования (`noindex, follow`) до авторского утверждения. Публикация и снятие `noindex` требуют отдельной проверки.

## Границы контента

Исходные формулировки главной страницы сохранены. Канонический текст Метода,
утверждённая биография, описания книг и практические материалы в репозитории
не предоставлены. Новые разделы явно помечены `Temporary content` и
`Awaiting approved materials`; они не содержат новых положений Метода,
биографических сведений, названий книг, отзывов или научных утверждений.

Временные разделы и шаблон книги имеют `noindex, follow`. Удалять `noindex`
можно после замены временных блоков утверждёнными материалами и проверки автором.
Canonical и `og:url` задают будущие постоянные адреса на существующем домене;
их наличие не означает публикацию или проверку DNS/HTTPS.

## Разработка в облачной среде

Из корня репозитория, Python 3.10 или новее:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8000/` в браузере **той же облачной среды**.
Ссылки и ресурсы используют пути от корня: обслуживать нужно весь репозиторий,
а не отдельную папку раздела. Режим `file://` и размещение в подпапке
`/shadrinmethod-website/` не поддерживаются без изменения путей. Целевой адрес
существующего сайта — корень домена из `CNAME`.

HTML хранится непосредственно в репозитории. При изменении общей навигации
обновлять все пять страниц и шаблон; текущий пункт отмечать `aria-current="page"`.
Общие визуальные изменения вносить в `assets/site.css`.

## Добавление страницы книги

1. Получить утверждённые автором название, описание и постоянный URL slug.
   Не создавать фиктивные книги для заполнения каталога.
2. Создать `books/<slug>/index.html` из `templates/book.html.template`.
3. Заменить `{{BOOK_SLUG}}`, `{{BOOK_TITLE}}`, `{{BOOK_DESCRIPTION}}` во всех
   местах, включая canonical и Open Graph. Slug должен состоять из латинских
   букв нижнего регистра, цифр и дефисов. Текст в HTML и атрибутах нужно
   экранировать (`&`, `<`, `>`, кавычки).
4. Заменить временный блок только утверждёнными материалами; добавить обложку
   и ссылки, только если они предоставлены. Не оставлять токены `{{…}}`.
5. Добавить ссылку на `/books/<slug>/` в `books/index.html`. У страницы книги
   в основной навигации текущим остаётся раздел Books.
6. Запустить проверки ниже и вручную проверить новую страницу на мобильном
   размере. Оба скрипта автоматически находят новые HTML-страницы;
   для вложенных страниц книг текущим пунктом ожидается `/books/`.
   Перед публикацией автор должен утвердить содержание и снятие `noindex`.

Шаблон не включён в навигацию и не является страницей книги.

## Технические проверки

Базовая проверка без сторонних зависимостей:

```sh
python3 scripts/check_site.py
git diff --check
```

Она проверяет все `*.html`: наличие страниц, цели локальных ссылок и якорей,
уникальность ID, один H1, язык, canonical, Open Graph, favicon и размеры PNG.
Это проверка структуры, а не полная HTML-валидация или аудит доступности.

Браузерная проверка (Playwright устанавливается только для разработки):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python scripts/check_browser.py --screenshots /tmp/shadrin-preview
```

В Codex Cloud с уже установленными Playwright и Chromium:

```sh
python3 scripts/check_browser.py --chromium /usr/bin/chromium --screenshots /tmp/shadrin-preview
```

Проверяются пять страниц на ширинах 320, 375, 768 и 1440 px, все переходы
основного меню, отсутствие горизонтального переполнения, переход клавишей Tab
к содержимому, якоря главной, reduced motion, ответы ресурсов и ошибки браузера.
HTTP-сервер запускается временно на `127.0.0.1` и закрывается после проверки.
Скриншоты — локальные артефакты проверки в облаке, они не публикуются.

Дополнительно можно запустить автоматические проверки axe-core WCAG 2.1 A/AA:

```sh
npm install --prefix /tmp/shadrin-axe --ignore-scripts --no-audit --no-fund axe-core@4.10.3
python3 scripts/check_browser.py --chromium /usr/bin/chromium --axe /tmp/shadrin-axe/node_modules/axe-core/axe.min.js
```

Автоматические проверки не заменяют ручную проверку экранным диктором,
контента и доступности на реальных устройствах.

## Проверка и выпуск

Изменения готовятся в отдельной ветке и передаются через Pull Request.
Stage 1 не содержит команд или workflow публикации, не меняет DNS и настройки
домена. PR не следует сливать до проверки автором: слияние может задействовать
существующие настройки GitHub Pages. Публикация требует отдельного утверждения
автора. Предварительный просмотр выполняется через временный сервер и скриншоты
в облаке.
